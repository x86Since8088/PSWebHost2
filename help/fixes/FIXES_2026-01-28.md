## Fix 1: File_Share_Roles PRIMARY KEY Constraint

### Problem
SQLite error when creating `File_Share_Roles` table:
```
SQL logic error expressions prohibited in PRIMARY KEY and UNIQUE constraints
```

The issue was using `COALESCE(UserID, GroupID)` in the PRIMARY KEY definition, which SQLite doesn't support.

### Solution
**File**: `system/db/sqlite/sqliteconfig.json`

**Changed FROM**:
```json
"primary_key": ["ShareID", "RoleType", "COALESCE(UserID, GroupID)"]
```

**Changed TO**:
```json
"primary_key": ["ShareID", "RoleType", "UserID", "GroupID"],
"check_constraints": [
  "(UserID IS NOT NULL AND GroupID IS NULL) OR (UserID IS NULL AND GroupID IS NOT NULL)"
]
```

**Explanation**:
- Removed COALESCE from primary key
- Added both UserID and GroupID to primary key (one will always be NULL)
- Added CHECK constraint to ensure exactly one is non-NULL
- This achieves the same logical constraint without using expressions in PRIMARY KEY

## Fix 2: Test Script Bearer Token Authentication

### Problem
`Test-UploadAndResume.ps1` was attempting to use unauthenticated requests, which would fail for protected endpoints.

### Solution
**File**: `Test-UploadAndResume.ps1`

**Added**:
1. **Test 3: Create Bearer Token**
   - Calls `Account_Auth_BearerToken_New.ps1`
   - Extracts API key from output
   - Stores in `$script:BearerToken` and `$script:Headers`

2. **Updated all HTTP requests** to use bearer token:
   ```powershell
   -Headers $script:Headers  # Instead of -WebSession $session
   ```

3. **Cleanup section** to remove token after tests:
   ```powershell
   & "$PSScriptRoot\system\utility\Account_Auth_BearerToken_Remove.ps1" `
       -Name $script:TokenName `
       -Confirm:$false
   ```

**Changes Made**:
- Test 2: Changed from version info check to simple root endpoint check
- Test 3: Renamed from "Authenticate" to "Create Bearer Token"
- Test 4-10: All HTTP requests now use `$script:Headers` with bearer token
- Cleanup: Added bearer token removal

## Fix 3: Suppress Excessive Init Output

### Problem
Every utility script invocation was showing:
```
.\init has already been loaded and -Force is not being used. Skipping.
```

This created excessive noise in test output.

### Solution
**File**: `system/init.ps1` (line 140)

**Changed FROM**:
```powershell
if ($PSWebHostDotSourceLoaded -and $global:PSWebHostGlobalLoaded -and -not $Force.IsPresent) {
    return Write-Host ".\init has already been loaded and -Force is not being used. Skipping."
}
```

**Changed TO**:
```powershell
if ($PSWebHostDotSourceLoaded -and $global:PSWebHostGlobalLoaded -and -not $Force.IsPresent) {
    return
}
```

**Result**: Silent return when init already loaded, reducing output noise significantly.

### 1. Better Error Handling
```powershell
try {
    # Token creation with output capture
    $tokenResult = & "$PSScriptRoot\system\utility\Account_Auth_BearerToken_New.ps1" ...
        2>&1 | Out-String
```

## Known Remaining Issues

### 1. Table Creation Error Messages
Even with the fix, you may still see this message on first run:
```
Table 'File_Share_Roles' not found. Creating it.
```

This is expected on first run or after table deletion. The important thing is that it succeeds without "SQL logic error".

### 2. Verbose Init Output
The following output is still shown during bearer token creation/removal:
```
[Init] Loaded app: DockerManager (v1.0.0)
... (app initialization messages) ...
```

This is from the apps being initialized when the system starts. To suppress this, you'd need to modify each app's app_init.ps1 to check if already initialized.

### 3. Performance Monitoring Messages
```
Stopping performance monitoring job...
Performance monitoring job stopped.
```

These messages are from WebHostMetrics being reloaded. They're informational and generally harmless.
